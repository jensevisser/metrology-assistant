# README — spiekbriefje

Wat een sterke README bevat. Voor dit project wordt hij aan het eind van Project 1 echt uitgewerkt ("Afronding" in CLAUDE.md §9).

## Altijd

- [ ] **Wat het is**, in 1–2 zinnen bovenaan.
- [ ] **Status**: waar het project staat (bijv. "Project 1, Sprint 0").
- [ ] **Vereisten**: wat er al geïnstalleerd moet zijn (bijv. Ollama, `uv`, een GPU met 12 GB).
- [ ] **Starten**: de exacte commando's, zodat een ander het kan draaien met alleen de README.
- [ ] **Licentie** (hier: MIT), plus waar documenten van derden vandaan komen.

## Als het project groeit

- [ ] **Projectstructuur** als klein boomdiagram:
  ```
  src/
    llm_client.py
  tests/
  eval/
  notes/
  ```
- [ ] **Scores**: evaluatieresultaten in een tabel (vóór/na, per backend).
- [ ] **Architectuurkeuzes en trade-offs**: waarom deze aanpak, wat was het alternatief.
- [ ] **Bekende beperkingen**: wat het (nog) niet goed kan.
- [ ] **"Wat ik hierna zou verbeteren"**: laat zien dat je op je eigen werk reflecteert. Werkgevers letten hierop.
- [ ] **Eigen bijdrage**: wat je zelf hebt gebouwd en kunt uitleggen.

## Optioneel

- [ ] **Badges** bovenaan (Python-versie, licentie), puur cosmetisch.
- [ ] **Screenshot of korte GIF** zodra er iets te zien is.
- [ ] **Inhoudsopgave** met links naar koppen, zodra de README lang wordt.
